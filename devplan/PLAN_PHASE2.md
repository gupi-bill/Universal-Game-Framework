## 推进原则（第二阶段专用）

1. **先证明通用性**：一切工作优先服务于「第二款游戏能端到端跑通」与「第三款游戏接入成本趋近于零」。
2. **可复现优于可演示**：每个结论都要有一条命令能复现，禁止"我跑了一下没问题"式的记录。
3. **每阶段必须产出自动化证据**（测试 / 门禁脚本 / 报告文件），不接受人工肉眼确认。
4. **Florr 深度拟人化不在本表**：依赖实机与真 VLM，本机不可验证，留待实机阶段单独立项。

## S15 · 第二款游戏端到端跑通（space_invaders）
- **目标**：让「通用框架」第一次被实证——用一份档案 + mock 感知，完整跑通 detect → brief → research → ensure → play → report。
- **任务**
  1. 按 S10 定下的档案规范补全 `game_profiles/space_invaders.yaml`（实体分类 / 威胁分 / 稀有度 / 套装 / 战术模板 / 感知端口），修正现存的稀有度与威胁分自相矛盾。
  2. 为 space_invaders 配置 mock 感知后端，实体分布符合该游戏语义（母舰 / 无人机 / 群兵 / BOSS）。
  3. 以 `UGF_DRY_RUN=1` 跑完整生命周期，确认每个阶段都有真实产出（不是空转）。
  4. 编写 `tests/test_e2e_space_invaders.py`：单条命令串起全流程，断言状态文件、知识库、报告均被正确写入。
- **交付物**：补全的档案、mock 配置、`tests/test_e2e_space_invaders.py`、`devplan/E2E_S15.md`。
- **验收**：端到端测试全绿；`AGENT_GAME=space_invaders` 下 dry-run 跑完退出码 0 且各阶段产物非空。

## S16 · 参考适配器模板与档案规范固化
- **目标**：让「接入新游戏」有标准答案，不再靠读 florr.yaml 猜。
- **任务**
  1. 产出 `game_profiles/_template.yaml`：全字段带注释的模板，含默认值与安全上下限。
  2. 写 `devplan/PROFILE_SPEC.md`（或更新 S10 产出的版本）：每个字段的类型、取值域、缺失时的兜底行为、常见错误示例。
  3. 让 `tools/add_game.py` 以模板为唯一来源生成档案，保证「生成即通过 validate」。
- **交付物**：`_template.yaml`、`PROFILE_SPEC.md`、改造后的 `add_game.py`、`tests/test_add_game.py`。
- **验收**：用模板生成一份全新档案 → `validate` 通过 → 核心能读到预期值；测试全绿。

## S17 · 接入流程一键化（onboard）
- **目标**：把「生成 → 校验 → 冒烟 → 试跑 → 出报告」压成一条命令，兑现「30 分钟接入一款新游戏」。
- **任务**
  1. 新增 `tools/onboard_game.py`：交互/参数两种方式，串起 add_game → validate → mock 感知冒烟 → dry-run N 轮 → 生成接入报告。
  2. 报告写入 `devplan/onboard_<game>.md`：档案摘要、冒烟结果、试跑轮数、发现的问题与建议。
  3. 接入 CLI：`agent_cli.py -c onboard <game>`。
- **交付物**：`tools/onboard_game.py`、`tests/test_onboard_game.py`、至少两份接入报告（含一款全新虚构游戏）。
- **验收**：对一款全新游戏跑 `onboard` 全流程，退出码 0 且报告非空；测试全绿。

## S18 · 知识闭环实证（学 → 检索 → 决策 → 复盘 → 回写）
- **目标**：把「越打越强」从文档措辞变成可复现的闭环，并给出可量化指标。
- **任务**
  1. 造 seed 知识（按游戏分类写入 `knowledge_md/<game>/`），确保检索能命中。
  2. 打通「决策前检索知识 → 命中条目进入 prompt/规则 → 结果写回」的链路，补上断点。
  3. 死亡复盘触发后确认新笔记落库，且下一轮能被检索到。
  4. 输出命中率指标：`learning_stats` 记录检索次数 / 命中次数 / 引用次数，可查询。
- **交付物**：`tests/test_knowledge_loop.py`（完整闭环）、`devplan/KB_LOOP_S18.md`（含实测命中率数字）、可能的 `kb_maintainer` / `agent_main` 修复。
- **验收**：闭环测试全绿；报告里有一组真实的命中率数字（不是占位符）。

## S19 · 学习链路离线化（视频 → 战术入库）
- **目标**：`video_learner` / `video_sources` 从未跑通过，需要在无网络无 VLM 下打通到「可实证」。
- **任务**
  1. 抽帧环节用合成帧（程序生成 PNG，不依赖下载与 cv2 硬依赖）。
  2. VLM 环节用可注入的 stub，返回结构化战术描述。
  3. 学完写库 → 自动清理临时帧（验证「小硬盘友好」原则真的生效）。
- **交付物**：`tests/test_video_learner.py`、`video_learner.py` 的可注入改造、`devplan/LEARN_S19.md`。
- **验收**：一次完整「抽帧 → 解析 → 入库 → 清理」测试通过；断言临时目录被清空、无残留文件。

## S20 · 决策场景矩阵（战斗 / 组队 / 心态 / 边界）
- **目标**：决策层不能只靠单测覆盖数学，要覆盖"局面"。
- **任务**
  1. 构造场景矩阵：以少打多 / 被包围 / 队友输出型 / 队友抗伤型 / 血量极低 / 实体突增突减 / 感知返回空 / 坐标全 NaN / 超高频抖动。
  2. 对每个场景断言决策结果（fight / cautious_fight / retreat）、推荐套装、心态档位符合预期。
  3. 发现的决策缺陷就地修复并补回归用例。
- **交付物**：`tests/test_decision_scenarios.py`、`devplan/SCENARIOS_S20.md`（场景 × 期望 × 实测表）。
- **验收**：矩阵全绿；场景表每一行都有实测值。

## S21 · 测试门禁与可观测性固化
- **目标**：一条命令验证整个项目，且运行时能看出「当前到底是什么模式」。
- **任务**
  1. `scripts/check.sh` / `Makefile`：`pytest` + `compileall` + `boot_check` + `mcp_tools_check` + CLI 冒烟，一条命令跑完，任一失败即非零退出。
  2. 监控大盘与 CLI 状态输出增加「运行模式」标识（online / dry-run / mock）与「感知后端」标识。
  3. 把门禁接入文档与 README。
- **交付物**：`scripts/check.sh`、`admin_panel.py` 模式显示改造、`tests/test_check_script.py`、`README` 门禁章节。
- **验收**：`bash scripts/check.sh` 退出码 0；大盘能正确显示 mock/dry-run 模式。

## S22 · 稳定性长跑与资源门禁
- **目标**：证明「7×24 可跑」不是口号，且不会把小硬盘吃掉。
- **任务**
  1. dry-run 长循环（≥500 轮或固定时长）测试：无异常退出、无内存单调增长（采样 RSS）、无句柄泄漏。
  2. 临时文件零残留证明：跑完断言 `video_frames/`、`run_logs/` 临时项、截图路径均无残留文件。
  3. 看门狗 `watchdog.sh` 与自恢复路径的离线验证（杀进程 → 自动拉起 → 状态恢复）。
- **交付物**：`tests/test_longrun.py`（或 `tools/longrun_check.py`）、`devplan/STABILITY_S22.md`（含内存/耗时曲线数字）。
- **验收**：长跑测试通过；残留文件断言为 0；报告含实测内存与轮耗时数字。

## S23 · 安全与合规加固
- **目标**：框架要能被别人放心使用与分发。
- **任务**
  1. 路径穿越复查：知识库读写、备份导入、档案加载，全部限制在项目目录内（S9 已修一处，此处做全量复查并加测试）。
  2. 密钥与敏感信息：确认 `.env` / 备份包 / 日志中不会泄漏密钥；加一条扫描测试。
  3. 档案沙箱：非法档案（超大数值、恶意键、循环引用）不导致崩溃，给出可读错误。
  4. README 与 PROJECT_SUMMARY 增补合规声明章节（本地/授权环境，不鼓励在他人服务器运行）。
- **交付物**：`tests/test_security.py`、文档合规章节、必要的代码加固。
- **验收**：安全测试全绿；恶意档案用例返回可读错误而非 traceback。
